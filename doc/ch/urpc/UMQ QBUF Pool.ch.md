# UMQ QBUF Pool

## 功能简介
UMQ QBUF Pool是UMQ组件的核心内存管理模块，提供高性能的内存分配和释放功能。该模块通过**线程本地缓存（TLS）和全局内存池**的双层架构，实现了低延迟、高并发的内存管理能力。

### 核心配置参数

QBUF Pool提供了三个关键的本地缓存配置参数，用于优化内存管理性能：

- **total_size**：内存池总内存大小
- **data_size**：每个block的大小
- **headroom_size**：用户头的大小
- **mode**：UMQ Buffer的模式，支持UMQ_BUF_SPLIT和UMQ_BUF_COMBINE两种类型
- **tls_alloc_batch_size**：从全局内存池批量获取buffer的数量
- **tls_free_batch_size**：向全局内存池批量返还buffer的数量
- **tls_buf_capacity**：本地线程缓存的总容量阈值

## 双层内存池架构

UMQ QBUF Pool的核心设计采用双层内存管理架构，这种设计旨在提升内存申请和释放的效率：

### 1. 线程本地缓存
每个线程拥有独立的内存缓存，避免了线程间的锁竞争。核心特点是：
- 线程私有，无需锁保护
- 内存分配和释放的首选来源
- 负责本线程内存资源的缓存

### 2. 全局内存池
所有线程共享的内存池，作为内存资源的总仓库和调度中心，核心特点是
- 所有线程共享，需要全局锁保护
- 作为本地缓存的补充和后备
- 负责内存资源的全局平衡

## 本地缓存阈值控制
- 本地缓存的最大容量由`tls_buf_capacity`参数控制
- 当本地缓存超过最大容量时触发返还，每次性归还`tls_free_batch_size`个buffer
- 确保每个线程不会占用过多内存资源
- 本地缓存不足时，从全局池获取buffer，每次获取`tls_alloc_batch_size`个buffer

## 内存分配与释放流程

### 内存分配流程

内存分配是QBUF Pool的核心功能，其流程体现了双层内存池的交互机制：

1. **内存池检查**：验证内存池是否已初始化
2. **本地缓存获取**：通过TLS获取当前线程的本地缓存
3. **需求计算**：根据请求参数计算实际需要的buffer数量
4. **本地分配尝试**：
   - 检查本地缓存中是否有足够的目标类型buffer
   - 如果足够，直接从本地链表分配
5. **全局池补充**：
   - 如果本地缓存不足，从全局池批量获取`tls_alloc_batch_size`数量的buffer
   - 更新本地缓存的buffer计数
6. **再次本地分配**：从补充后的本地缓存中分配所需buffer
7. **Buffer初始化**：设置buffer元数据并标记为已分配状态
8. **结果返回**：返回分配的buffer链表

### 内存释放流程

内存释放流程与分配流程相对应，同样体现了双层内存池的交互：

1. **内存池检查**：验证内存池是否已初始化
2. **本地缓存获取**：通过TLS获取当前线程的本地缓存
3. **Buffer类型判断**：根据内存地址判断是有数据buffer还是空buffer
4. **本地缓存释放**：
   - 将buffer添加到本地缓存的对应链表
   - 更新本地缓存的buffer计数
5. **阈值检查**：
   - 检查本地缓存中的buffer数量是否超过`tls_buf_capacity`
   - 如果超过，将`tls_free_batch_size`数量的buffer放回全局池
   - 更新本地缓存和全局池的计数
